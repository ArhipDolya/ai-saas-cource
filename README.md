# ai-saas-cource

Фінансовий Telegram-бот на aiogram 3.x із записом витрат у PostgreSQL (Neon).

## Вимоги для Docker

- Docker із Docker Compose (наприклад, запущений Docker Desktop).
- Токен Telegram-бота від [BotFather](https://t.me/BotFather).
- Доступ до інтернету.

Встановлювати Python на комп’ютер для запуску через Docker не потрібно.

## Структура

```text
app/main.py       # Запуск бота й обробник /start
app/database.py   # Підключення та початкова ініціалізація схеми
app/models.py     # Таблиці users, categories, transactions і зв’язки
app/expenses.py   # Перевірка та збереження витрат
check_db.py       # Перевірка доступу до PostgreSQL
requirements.txt  # Python-залежності
.env              # Локальний BOT_TOKEN, виключено з Git
.env.example      # Приклад налаштувань без секретів
README.md         # Інструкція запуску
Dockerfile        # Образ із Python, залежностями та кодом
docker-compose.yml # Запуск із hot reload для розробки
.dockerignore     # Виключення секретів і локальних файлів з контексту збірки
```

## Запуск через Docker

Якщо `.env` ще немає, створіть його з прикладу:

```bash
cp .env.example .env
```

У `.env` встановіть власний `BOT_TOKEN` і `DATABASE_URL` із Neon. Перед запуском зупиніть локальний процес бота через `Ctrl+C`, якщо він працює: два процеси polling з одним токеном конфліктують.

З кореня проєкту виконайте:

```bash
docker compose up --build
```

Команда збере образ, встановить залежності й запустить бота. Логи з’являться в цьому ж терміналі. Надішліть `/start` своєму боту в Telegram.

Щоб зупинити бота, натисніть `Ctrl+C`. Щоб також видалити контейнер і мережу цього Compose-проєкту:

```bash
docker compose down
```

## Hot reload

Під час роботи `docker compose up --build` змінюйте та зберігайте Python-файли в `app/`. Compose монтує локальну папку в контейнер, а `watchfiles` автоматично перезапускає процес бота після змін. Сам контейнер і образ при цьому залишаються тими самими.

Для перевірки змініть `START_GREETING` у `app/main.py`, збережіть файл і дочекайтеся повідомлення про перезапуск у логах. Надішліть `/start` ще раз: бот має відповісти новим текстом. Зміни в підпапках `app/` також відстежуються.

`WATCHFILES_FORCE_POLLING=true` вмикає періодичну перевірку файлів, щоб зміни в змонтованій папці на Docker Desktop виявлялися надійно. Це додає невелике навантаження; відстежується лише `app/`.

Для інших змін:

| Що змінилося | Що виконати |
| --- | --- |
| Python-код у `app/` | Просто зберегти файл |
| `requirements.txt` або `Dockerfile` | `docker compose up --build` після зупинки поточного запуску |
| `.env` | `docker compose up -d --force-recreate bot` |
| `docker-compose.yml` | Зупинити поточний запуск і виконати `docker compose up --build` |

Звичайний `docker compose restart` не перечитує `.env`: для нового значення потрібне перестворення контейнера. `.env` передається через `env_file` під час запуску й не копіюється в образ.

Цей режим hot reload призначений для розробки.

## Локальний запуск без Docker

Потрібен Python 3.10 або новіший. Не запускайте локального бота одночасно з контейнером.

Виконайте з кореня проєкту (macOS / Linux):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Якщо `.env` ще немає, створіть його з прикладу:

```bash
cp .env.example .env
```

У `.env` замініть `your_bot_token_here` на власний токен, а `your_database_url_here` на рядок підключення до Neon. Не додавайте справжній токен або URL із паролем у код, README чи `.env.example`.

```bash
python -m app.main
```

Бот автоматично читає `.env` з кореня проєкту. Уже встановлений `BOT_TOKEN` у змінних середовища має пріоритет над `.env`.

При запуску бот створює відсутні таблиці `users`, `categories`, `transactions` та додає відсутній складений зв’язок категорії з її власником. Наявні таблиці та записи зберігаються. Це початкова ініціалізація, а не система міграцій для довільних майбутніх змін схеми.

## Додавання витрат

Надішліть боту:

```text
/expense 120 кава
```

Після збереження бот відповість:

```text
Витрату створено: 120.00 грн, категорія: кава.
```

Бот визначає користувача за Telegram ID автора команди, створює його за потреби та знаходить або створює його категорію. Кожна коректна команда додає нову витрату. У різних користувачів категорії незалежні; назви категорій чутливі до регістру.

Сума має бути від `0.01` до `9999999999.99` грн з максимум двома десятковими знаками. Підтримуються крапка й кома (`120.50`, `120,50`) та назви категорій із пробілами (`/expense 120 кава з собою`). Назва категорії має містити не більше 100 символів. Зайві пробіли в назві прибираються.

Користувач, категорія та витрата записуються однією транзакцією. Підтвердження надсилається після успішного commit. Якщо база недоступна, бот повідомляє, що запис не вдався. `/help` показує приклад команди.

Схема використовує `bigint` для ідентифікаторів, `numeric(12, 2)` для грошей і серверний `created_at` у кожній таблиці. Унікальність `(user_id, name)` запобігає дублюванню категорії одного користувача. Складений зовнішній ключ `(category_id, user_id)` забороняє записати витрату в категорію іншого користувача. Наявні додаткові поля Neon (`transaction_type`, `description`, `transaction_date`) використовують свої значення за замовчуванням.

## Перевірка

1. Залиште процес запущеним у терміналі.
2. Відкрийте свого бота в Telegram і надішліть `/start`.
3. Переконайтеся, що бот відповідає: «Привіт! Бот працює 👋».
4. Натисніть `Ctrl+C` у терміналі, щоб зупинити бота.

Бот використовує long polling: він сам отримує оновлення від Telegram. Для запуску не потрібні nginx, ngrok або відкриті порти. Запускайте лише один процес polling для одного токена.

Якщо `BOT_TOKEN` відсутній або порожній, застосунок завершиться з поясненням. Якщо Telegram відхиляє авторизацію, перевірте токен у BotFather. Токен, оприлюднений у чаті або репозиторії, перевипустіть через BotFather та замініть у `.env`.

## Перевірка підключення до бази даних

Додайте `DATABASE_URL` із Neon до локального `.env`, зберігши параметри SSL у рядку підключення. Не додавайте справжній URL із паролем у Git.

Для перевірки без Docker виконайте з кореня проєкту:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python check_db.py
```

Скрипт виконує `SELECT 1` через SQLAlchemy й виводить `OK`, якщо підключення та запит успішні. Якщо `DATABASE_URL` відсутній, має неправильний формат або база недоступна, виводиться `Not OK`. Код завершення: `0` для успіху, `1` для невдачі.

Перевірка не створює таблиць і не змінює дані. Вона підтверджує доступ до бази та виконання простого запиту; структуру таблиць і права на запис потрібно перевіряти окремо.
